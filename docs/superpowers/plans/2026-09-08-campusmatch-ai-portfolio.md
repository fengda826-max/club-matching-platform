# CampusMatch AI Portfolio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a public, two-day portfolio PoC that demonstrates customer discovery, explainable AI matching, grounded streaming Q&A, operational metrics, graceful degradation, and low-cost Tencent Cloud deployment.

**Architecture:** Keep the Vue 3 + Express + Prisma application as a modular monolith. Deterministic services own filtering and scoring; DeepSeek V4 extracts preferences and writes explanations through a provider-neutral gateway; Docker Compose runs Nginx and the Node.js application on one Tencent Cloud Lighthouse instance with a persistent SQLite volume.

**Tech Stack:** Vue 3, TypeScript, Pinia, Vue Router, Element Plus, Express, Prisma, SQLite, Zod, Vitest, Supertest, DeepSeek V4 OpenAI-compatible API, Docker Compose, Nginx, Tencent Cloud Lighthouse

**Spec:** `docs/superpowers/specs/2026-09-08-campusmatch-ai-portfolio-design.md`

## Global Constraints

- Target only cloud solution, pre-sales architecture, and AI application solution roles.
- Complete one coherent PoC; do not introduce microservices, Kubernetes, Redis, a message queue, a managed database, or a vector database.
- DeepSeek V4 is the live model; Tencent TokenHub remains an optional provider boundary and README selection note.
- AI may extract preferences and generate language, but deterministic code owns hard constraints and scores.
- The application must still browse clubs and return rule-only recommendations without an AI API key.
- Do not store raw prompts, names, phone numbers, student numbers, or other personal information in analytics tables.
- Public users may see sanitized demo metrics; every club write operation requires server-side admin authentication.
- Keep the existing five-page navigation and remove features before adding pages.
- All resume metrics must be generated by tests or telemetry; never invent success rates, latency, or cost figures.
- Preserve unrelated user changes, including the untracked `AGENTS.md` file.
