# CampusMatch AI 五分钟面试演示脚本

## 0:00–0:30｜客户问题

打开首页：新生真正缺的不是“更多社团列表”，而是把时间、费用、校区、门槛统一比较；运营方真正缺的是推荐后的意向转化和模型运行证据。

## 0:30–1:30｜自然语言提取

进入“智能匹配”，使用：`周末有时间，零基础但喜欢编程，希望参加比赛，每周最多投入 4 小时，费用不超过 50 元。`

点击“让 AI 提取条件”。强调原文保留、结果可编辑、确认后才进入决策。如果模型不可用，直接填写兴趣“编程”、目标“竞赛”、时间“周六”、水平“零基础”、每周 4 小时、费用 50 元。

## 1:30–2:30｜评分、证据与风险

点击“计算可解释匹配”。说明硬约束先排除不合适项；兴趣 40、目标 25、时间 20、技能 15 均由代码计算。展开第一项，指出数据库证据、每周投入和费用注意事项。强调模型不能改分，也不能添加候选之外的社团。

## 2:30–3:30｜有依据的流式问答

进入“AI 问答”，询问：`编程初学者周末有哪些选择？费用和每周投入分别是多少？`

指出回答逐步输出，底部“回答依据”来自本次检索的社团记录；点击停止生成可取消上游请求。资料没有写明时，模型被要求明确说明未知。

## 3:30–4:00｜意向与转化

返回匹配结果，点击“我想进一步了解”。重复点击时显示已记录，不重复计数。进入运营驾驶舱，刷新后展示推荐请求、有效意向和转化率。

## 4:00–5:00｜云架构与取舍

展示 README 架构：腾讯云轻量服务器上由 Nginx 作为唯一入口，Express 模块化单体连接 SQLite 持久卷，后端网关调用 DeepSeek V4。说明：

- API Key 不进浏览器，写接口有服务端鉴权。
- 模型输出经 Zod 校验，瞬时故障有界重试。
- 无 Key、超时、非法 JSON 或虚构 ID 时，推荐降级为规则结果。
- 当前业务量不需要 Kubernetes、Redis、微服务和向量库；README 写明了演进触发条件。

## 故障恢复

演示前保留一张“规则模式”匹配结果截图。网络故障时把 `AI_API_KEY` 临时置空并重启应用，直接演示结构化表单与规则结果；不要口头假装模型仍在线。运行 `docker compose ps` 和 `docker compose logs app --tail 100` 定位容器问题。
